## Section H — Cross-subsystem assumptions (for Phase 3 design doc)

Items Boyu (Red AI), Oskar (Blue AI), and the Milestone J worker
will need to know. Phase 3 commits a single omnibus doc
`team-missile-intercept/game-core/CONTRACT_SEAMS.md` covering:

### H1. Phase transition table + allowed WS commands per phase

- Four phases: SETUP, RUNNING, PAUSED, FINISHED.
- Six legal transitions (per `types.LEGAL_PHASE_TRANSITIONS`).
- Self-transitions and the rest of the 16-tuple cross-product are
  illegal and return False from `World.transition`.
- WS commands legal per phase:
  - `start`: legal only in SETUP.
  - `pause`: legal only in RUNNING.
  - `resume`: legal only in PAUSED.
  - `reset`: always legal (short-circuits FSM by rebuilding World).
  - `speed`: phase-agnostic, affects sim_steps_per_stream.
- Illegal commands return `{"type":"error","reason":"illegal_transition","from":p,"to":p}`
  to the sender only (not broadcast).

### H2. `World.spawn_threat` / `World.spawn_interceptor` contract

- Covered by D1 / D2 docstrings in Phase 2.
- Key cross-team rule: **post-spawn mutation is not supported**. A
  caller who wants per-tick Red AI control must use
  `Threat.override_maneuver`, not mutate `threat.waypoint` directly.

### H3. `Scenario.step` invariants

- **Always true between ticks:**
  - `world.events` is empty right after `Scenario.step` returns
    from a non-RUNNING phase (we clear at the top regardless).
  - `world.t` is monotonically non-decreasing (only advances in
    RUNNING).
  - Dead entities are pruned (via `prune_dead` at the end of a
    RUNNING tick) so `world.threats.values()` contains only live
    entities.
- **Caller must not mutate during tick:** read-only snapshots only.
  Red / Blue AI `step` methods run INSIDE `Scenario.step` and are
  allowed to call `world.spawn_*`; any other external mutator is on
  thin ice.
- **Post-tick auto-FINISHED:** if `Scenario.winner` is non-None and
  phase was RUNNING, the step auto-transitions to FINISHED.

### H4. Event dict schema (inventory from E1-E3)

Document the event dicts that consumers can rely on. Table maps
`type` → expected fields. Notes on `hit_kind` additive compatibility.

### H5. Red AI `_pick_target` → `target_site_id` transition plan

Today `_pick_target` returns `(x, y)` (site coordinates). Issue 10-11
in `ISSUES_2026-04-19.md` proposes a `target_site_id: int` field on
Threat. Contract-seams doc notes the future shape without committing
to it.

### H6. Pattern constraint for future phase-gating

If someone adds phase-gating to `World.step` itself (today it's only
at `Scenario.step`), every test that drives `world.step()` directly
(Pattern 1 in Section B) turns into a silent no-op. Document: any
new phase-gating layer MUST also update the direct-World tests to
walk SETUP → RUNNING, OR keep the gate at the Scenario level.
